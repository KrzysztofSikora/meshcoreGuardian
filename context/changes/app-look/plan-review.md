Grounding notes (verified, no finding):
- The `expo-font` 57.0.4 plugin supports `android.fonts[{ fontFamily, fontDefinitions[{ path, weight }] }]` and registers the family name verbatim through `ReactFontManager.addCustomFont` (`apps/mobile/node_modules/expo-font/plugin/build/withFonts.d.ts`, `withFontsAndroid.js`), so `"IBM Plex Sans"` with `fontWeight` works as the plan says.
- All cited lines check out: `index.tsx:111`, `nearest-repeater-card.tsx:137`, `node/[id].tsx:203`, `presenter.ts:73-86`, `run-status.tsx:15`, `presenter.test.ts:114`, `connection-status.tsx:5-10`, `eslint.config.mjs:112` (rule at ~117), `_layout.tsx:10-16`, the 17 e2e flows and the `diag-no-reply` scenario.
- The mockup's light pairs pass 4.5:1 (lowest: muted on segment track 5.25, ok-chip 5.36). The proposed dark pairs in D-10 also pass (on-accent 7.84, muted on surface 7.35), so the contrast test will not force a departure from the mockup.
- `presenter.ts` is not a mutation target in `context/test-plan.md` § *Mutation targets*, so no mutation obligation follows from the lesson.

## Decisions the PR reviewer should look at
- D-1: `react-native-svg` pulled into a look-only slice (costly, new native dependency). It is isolated behind `<Icon>`, so it can be reverted cleanly.
- D-2: about 1.2 MB of font binaries committed to git, with the licence notice deferred to S-10 (OFL).
- D-10: the dark palette is agent-derived because the mockup has no dark artboards. Only the human check judges whether it looks right.
- D-5: a custom bottom nav inside the Stack instead of expo-router `Tabs`. It keeps today's back behaviour, but S-09 and later slices inherit it.

## What is good
- Clear invariants that can be checked: `en.json` diff empty, no logic change outside the presenter look table, every existing e2e flow unchanged, full e2e in each UI phase (lesson on list height applied).
- Out of scope is explicit and lists every mockup element that would need new text or data. This applies the roadmap's "copy stays as in `en.json`".
- The contrast proof is a pure unit test over declared pairs. Tone and icon live as pure data in the application layer, so NFR-05 is unit-testable and layering holds.
- D-6 and D-7 map the mockup's artboards onto the real routes without logic changes, and spot the duplicated titles that exist today.
