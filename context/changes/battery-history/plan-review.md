| 3 | major | Failure paths / Phasing (Phase 5) | `samplesFromChecks` sets `measuredAt = check.startedAt + check.durationMs` and only falls back to `finishedAt` when those are null (`packages/domain/src/telemetry/samples.ts:105-108`). | 5 | minor | Phasing (Phase 1 tests) | "the band edge (\|change\| = 0.05 → not stable)": the fitted change is slope × span in floating point, so an exact 0.05 may come out as 0.04999… and the test becomes flaky or misleading. | Test 0.049 / 0.051 (or construct exactly representable inputs) and say which comparison (`<` vs `<=`) is intended. |
| 6 | minor | Grounding | Row value precision is not given. The design gives y labels "to 2 decimals" and the e2e expects "3.35 V", while D-1 argues for status because of its mV resolution (3.353 V). ## Decisions the PR reviewer should look at
- D-6: new runtime dependency via an undocumented deep import (`react-native-gifted-charts/dist/LineChart`), unproven on RN 0.86 / New Architecture. The peers `expo-linear-gradient` and `react-native-linear-gradient` are `optional: true` in `peerDependenciesMeta` and `autoInstallPeers: false` (`pnpm-workspace.yaml:23`), so the "no gradient package" claim holds. The fallback to hand-written SVG is isolated to one file.
- D-1: one point per run, status preferred over telemetry, reads FR-12 AC1 "each sample" as "each run". This is a defensible interpretation, but it is a reading of the AC.
- D-5: AC4 shows only when the node has samples and none has voltage, and the 0 mV → null rule it relies on is `UNVERIFIED` (S-06 D-5).

## What is good
- Every cited file and symbol checks out: `ports.ts:3`, `telemetry-repository.ts:6`, migration 0004 columns and index, the `NodeHistoryController` `Promise.all` with keep-previous-data, the `shown` derivation from `loaded` (`app/node/[id].tsx:129-135`), and the fake-only guard in `debug/scenario/[name].tsx`.
- The A-01 gate and the "no prediction" rule from the roadmap's *Decided up front* are enforced in two places: by the type shape with a key-pinning test, and by a catalog word-ban test (D-11).
- It follows the lesson on empty-data messages (D-5) and the lesson on added height (Phase 4 greps the affected flows and runs the full suite).
- Phases are ordered by dependency (domain → storage → application → UI → seed/e2e), and each phase runs gates from the `CLAUDE.md` table.
- Proportional x spacing (D-7) and the honest "fitted change" wording (D-4) fit the product's honest-status principle.
