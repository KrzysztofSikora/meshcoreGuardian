# Plan: pilot-release (S-10)

## Goal and end state
- An EAS Build `production` profile produces a signed AAB that can be uploaded to the Play internal
  testing track (FR-20 AC1). The release manifest asks only for the permissions the app uses.
  Uploading is a human step, and credentials never enter the repo.
- `docs/privacy-policy.md` describes the local-only data handling. The same text can be read
  in the app, offline (Settings → Privacy policy). A person publishes it at a public URL (FR-20 AC2).
- Settings → Open-source licences lists the notices of every JS package shipped in the bundle,
  with meshcore.js (MIT) and IBM Plex (OFL) pinned first.
- `docs/accessibility-audit.md` records contrast, labels, colour-only status and 200 % font scale
  per screen, and fixes the failures it finds (NFR-05).
- `docs/performance.md` records an emulator profiler trace (frame stats) with a seeded 200 nodes
  and 1,000 runs, plus cold start time. Measuring on the mid-range phone is a human check (NFR-06).
- Success criteria (definition of done): the pilot checklist in `docs/release.md` names the
  hardware checks a person signs off before inviting testers.

## Scope
- In: `eas.json`, app version, release manifest permissions (repo-skeleton `[FOLLOW-UP]`),
  release runbook, privacy policy (doc and in-app screen), licences screen (app-look
  `[FOLLOW-UP]`), accessibility audit with fixes, large-history seed, perf trace script and
  record, CI option to build a fake-transport APK for the phone trace.
- Out: uploading to Play, `eas init`/login, publishing the policy URL, the Data safety form
  (human steps, listed in `docs/release.md`); notices for native Android libraries (AndroidX,
  Hermes, …) → `[FOLLOW-UP]`; performance optimisations not shown to be needed by a trace;
  Polish locale; iOS; other open follow-ups from earlier changes (settings races, incremental sync).

## Findings
- `apps/mobile/app.json`: `version` `0.0.0`, no `versionCode`, no `eas.json` anywhere, no
  `extra.eas.projectId`. `android/` is generated by prebuild and gitignored.
- CI `android-apk` (`.github/workflows/ci.yml:46-99`) builds a debug-signed release APK with the
  real BLE transport. It stamps `version`/`versionCode` with `jq` and says "Not a Play release (that is S-10)".
- Repo-skeleton `[FOLLOW-UP]` (`context/changes/repo-skeleton/plan.md:348`): the generated manifest
  contains Expo's default `INTERNET`, `SYSTEM_ALERT_WINDOW`, `VIBRATE`,
  `READ/WRITE_EXTERNAL_STORAGE`. These should be removed before the pilot.
- App-look `[FOLLOW-UP]` (`context/changes/app-look/plan.md:331`): add a licences screen listing IBM
  Plex (OFL, `apps/mobile/assets/fonts/OFL.txt`) and meshcore.js (MIT). The tech stack requires the
  meshcore.js notice in the app. The notice is at `node_modules/@liamcottle/meshcore.js/LICENSE`
  ("Copyright (c) 2025-2026 Liam Cottle").
- `pnpm licenses list --prod --json --filter mobile` returns 487 packages, including build-time
  tooling (`@expo/cli`, …), and leaves out meshcore.js because it does not follow workspace
  packages. So it is the wrong source for "what ships".
- Settings About card: `apps/mobile/src/app/settings.tsx:170-192`; its texts come from
  `application/settings/presenter.ts` (`settingsView`). The Screen component
  (`components/ui/screen.tsx`) takes `scroll`; long lists use `FlatList`
  (`app/index.tsx:101`, `app/node/[id].tsx:80`).
- Node history shows the latest `RECENT_RUNS = 50` runs
  (`application/nodes/node-history.ts:12`). The voltage chart loads the runs of its range
  (`forNodeBetween`). The trace therefore covers the dashboard list (200 rows), the 50-row
  history and a chart range with hundreds of points.
- Debug seed route `app/debug/seed/[name].tsx` (fake build only) knows `voltage-history`. Nodes
  can be stored through `NodeRepository.applySync(reports, { complete, now, origin })`
  (`packages/domain/src/nodes/ports.ts:19`), and runs through `RunRepository.save`.
- Contrast is already checked per token pair by `apps/mobile/src/theme/contrast.test.ts` (app-look
  D-11). TR-19 leaves "the rest" of the label/200 % audit to S-10.
- `AppButton` sets `accessibilityRole="button"` and takes an optional `accessibilityLabel`
  (`components/ui/button.tsx:50`). Bottom nav tabs set role and selected state
  (`components/ui/bottom-nav.tsx:41`).
- The repo is **private** (`gh repo view`), so a GitHub file URL is not a public URL for AC2.
- EAS (docs.expo.dev, `submit/android`, `build-reference/app-versions`, `build/automate-submissions`):
  - the `production` profile builds an `.aab` by default;
  - `cli.appVersionSource: "remote"` together with `autoIncrement: true` keeps `versionCode` on EAS;
  - the submit `track` defaults to `internal`, and `releaseStatus: "draft"` leaves promotion in the Play Console;
  - **the first upload of a new app must be done manually in the Play Console**.
- Google Play User Data policy (support.google.com/googleplay/android-developer/answer/10144311):
  every app needs a privacy policy in two places. One is the Play Console field, which must hold
  an active, public, non-geofenced URL (not a PDF). The other is a link to the policy, or its
  text, inside the app. This applies even to apps that collect no personal data. The policy must
  name a privacy contact and describe retention and deletion. The Data safety form must match it.

## Design
- **Release config** (`apps/mobile/eas.json`):
  - `cli`: `appVersionSource: "remote"` and a `version` range for eas-cli;
  - `build.production`:
    - `autoIncrement: true`;
    - `android.buildType: "app-bundle"`;
    - `env.NODE_ENV: "production"`, with no `EXPO_PUBLIC_TRANSPORT`, so the real BLE transport is used;
    - `node: "24"` and the pnpm version from `packageManager`, if EAS accepts the field (see Risks);
  - `build.preview`: `android.buildType: "apk"` (internal distribution, optional);
  - `submit.production.android`: `track: "internal"`, `releaseStatus: "draft"`.
  - No `serviceAccountKeyPath` is committed; `docs/release.md` says to keep the key outside the repo.
- **Release manifest**: `app.json` gets `android.blockedPermissions` (D-2). The plugin
  `with-release-no-internet.js` uses `withDangerousMod("android")` to write
  `app/src/release/AndroidManifest.xml`:
  `<manifest xmlns:tools=…><uses-permission android:name="android.permission.INTERNET" tools:node="remove"/></manifest>`.
- **Licences**:
  - `notices.json` is an array of `{ name, version, license, text, source: "npm" | "asset" }`;
    an entry with no licence file gets `text: null`;
  - `application/about/licenses-presenter.ts` provides `licenseRows(notices)`: pinned rows first,
    then sorted, then a row view with `textKey` for a missing text ("Licence text not included in
    the package; licence: {{id}}");
  - the screen renders only presenter output.
- **Privacy policy**: catalog keys `privacy.title` and `privacy.p1 … pN`. Sections:
  - what the app stores (nodes, runs, telemetry, settings) and where (on the device only);
  - guest passwords (Keystore-backed secure storage, never exported);
  - no network: no account, no analytics, no crash reporting, no network permission;
  - Bluetooth use (only to talk to the user's companion; no location use);
  - exports (only when the user shares them; public keys redacted by default);
  - retention and deletion (Settings → Delete/Clear, or uninstall);
  - children; changes to the policy; contact (D-6).

  `presenter`: `privacyParagraphs()` returns the ordered keys. The drift test reads `en.json` and
  `docs/privacy-policy.md`.
- **Seed**: `debug/large-seed.ts` provides two functions, both deterministic for a given `now`:
  - `largeSeedContacts(now): ContactReport[]`;
  - `largeSeedRuns(now, companion): DiagnosticRun[]`.

  They reuse the status-check shape from `voltage-seed.ts` (shared helper moved, not copied).
- **Perf script** `scripts/perf-trace.sh`:
  - emulator only (refuses non-`emulator-*` serials, like `scripts/e2e.sh`);
  - reuses the fake release APK (`E2E_SKIP_BUILD`) or builds it through `scripts/e2e.sh`'s build path;
  - runs `apps/mobile/e2e/perf/large-history.yaml`: seed, then scroll the dashboard top to bottom,
    open the seeded node, scroll the history, switch the chart range to 30 days;
  - wraps the flow with `adb shell dumpsys gfxinfo <pkg> reset` before and `dumpsys gfxinfo <pkg>`
    after, so the evidence covers that flow only;
  - measures cold start 5 times (`am force-stop`, `am start -W`) and records `TotalTime` and the median;
  - writes everything to `evidence/perf-emulator.txt`.

  `perf/` is a subfolder, so `maestro test apps/mobile/e2e` does not run it.
- **200 % font shots** `scripts/a11y-shots.sh`:
  - emulator only;
  - `adb shell settings put system font_scale 2.0`, with a trap that restores the previous value;
  - runs `apps/mobile/e2e/audit/screens.yaml`, which reuses `lib/look-screens.yaml`'s navigation
    and adds the licences and privacy screens, with `takeScreenshot`;
  - downscales the PNGs to stay under 300 KB.

## Risks and unknowns
- R-05 Play Console account readiness: the human steps in `docs/release.md` cannot run without it.
  The plan does not depend on it to stay green.
- EAS with pnpm 12 and a hoisted monorepo: EAS images may ship another pnpm. If the `pnpm` field
  is not accepted by the eas.json schema, rely on `packageManager` and corepack. If the cloud build
  fails, `eas build --local` uses the local toolchain; record a `[REVIEW]` deviation.
- Removing `INTERNET` could break a module that opens sockets at start-up. The Phase 1 e2e runs on
  the release APK guard against this. Fallback: D-2 option B, logged as `[REVIEW]`.
- `expo export --source-maps` flag names differ between SDKs; check `expo export --help` at
  implementation. The fallback is `--dump-sourcemap`.
- The emulator frame stats are not phone numbers; the NFR-06 verdict is the phone human check.
  If the phone misses 55 fps, the fix is a new change (`[FOLLOW-UP]`), not hidden tuning here.
- The audit may find more failures than one phase can hold (~400 lines). Then split Phase 4 into
  4a/4b and log a `[minor]` deviation.
- Second phone (Android 12, other vendor; test-plan device matrix) is a human check in
  `docs/release.md`'s pilot checklist.
