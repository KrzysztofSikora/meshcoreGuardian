## Decisions the PR reviewer should look at
- D-3: cancel after a reply is stored as `NOT_TESTED`. This follows PRD AC3 and overrides the roadmap's best-evidence rule, and the node's last status will read "Last test cancelled" even though it answered.
- D-2: the run stops at the first check that got no reply, so a silent login means status is never tried. It saves airtime but yields less evidence.
- D-14: the airtime notice is shown once and persisted for good, while the PRD says "first diagnostic of a session". The plan reads "remembered" as winning over that.
- D-1 / D-8 (costly): the reason vocabulary and the schema are stored values. Both are isolated in domain and one migration, and both match the roadmap's two-table rule.
- D-4: the timeout margin is ×2 with a 5 s floor, but only direct-path samples exist (flood unknown).

## What is good
- Grounding is precise. Frame seqs 362-378 and 219, the encoders (`connection.js:230-253`), the decoder kinds, `FakeTransport` matching by first unconsumed code (which makes `remoteScript ×3` work for retries), the catalog forbidden-words test, the 9 → 15 e2e count and the existing `stryker.targets` entries all check out.
- Classification, the stop rule and the rules live in domain, and orchestration lives in `MeshClient`, as the tech stack and roadmap require. The mapped-type `RULES` makes a missing result × reason pair a compile error.
- Honest-status details are deliberate. The `sent` ack is kept apart from a remote no-reply (D-5), unknown errors get a neutral reason (D-11, lesson), unrelated malformed pushes are ignored (D-9), and the per-check timeout source is stored and shown.
- Each phase carries concrete boundary values (TR-03), and the lesson about writing a minimal transport double is applied in Phase 4.
